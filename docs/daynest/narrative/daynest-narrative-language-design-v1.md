# DayNest 叙事语言设计 v1

## 1. 目的

本文定义 DayNest 的中文优先叙事语言方向。

这是一次纯文档设计，不批准任何运行时代码改动。

已确认边界：

- 现有 MoodNest 行为必须保持不变
- DayNest 当前仍是本地优先的个人成长账本方向
- 叙事语言应服务于低压力行动、可见积累、休息恢复、回望反思与用户自定义奖励
- 叙事语言不能取代清晰的功能表达
- 叙事语言不能把休息描述为失败

## 2. 核心叙事命题

DayNest 的核心隐喻不是冲刺，不是打榜，也不是催促。

更合适的命题是：

- 人生像一条慢慢向前延展的路
- 有意义的行动，会在路上留下小小的光
- 这些积累下来的光，会帮人照亮接下来的一段路
- 停下来也可以，坐在路灯旁歇一歇，也是旅程的一部分

推荐核心表达：

- DayNest 不是一个催你快一点的系统
- DayNest 帮你收集一路上留下的小小微光
- 前行、暂停、回望、兑换心愿，都属于这段路
- 休息不是失败，而是为了继续走下去保留力气

## 3. 四个叙事动作

DayNest 的叙事动作建议围绕四个词展开。

### 前行

适用场景：

- 完成任务
- 完成子任务
- 完成习惯打卡
- 完成专注时段

叙事含义：

- 往前走了一小段
- 留下了新的行动痕迹
- 为未来积累了新的光

### 停靠

适用场景：

- 休息
- 暂停窗口
- 低能量日
- 恢复期

叙事含义：

- 不是退出
- 不是掉队
- 而是暂时把脚步放缓，让旅程继续可持续

### 回望

适用场景：

- 日历
- 统计
- 时间线
- 月度结算

叙事含义：

- 回头看已经走过的路
- 看见沿途留下的足迹、光点和阶段变化
- 帮助用户承认已经发生的积累

### 点亮

适用场景：

- 使用积累的虚拟奖励
- 为自己兑换愿望或休息

叙事含义：

- 不是消费冲动
- 而是把一路收集来的光，点亮一个自己真正在意的小心愿

## 4. 中文优先术语表

以下是推荐的默认中文叙事标签。

| 概念 | 推荐中文 |
| --- | --- |
| 整体进度积累 | 成长值 |
| 分类成长维度 | 成长方向 |
| 可消耗的虚拟奖励资源 | 微光 |
| 用户可见的余额容器 | 提灯 |
| 虚拟奖励交易历史 | 微光记录 |
| 奖励目录 / 心愿清单 | 心愿单 |
| 单个奖励项 | 心愿卡 |
| 奖励页的可选叙事标题 | 心愿驿站 |
| 奖励兑换动作 | 点亮心愿 |
| 长周期任务的叙事隐喻 | 路线 |
| 里程碑的叙事隐喻 | 路标 |
| 日历或时间线上的可见行动痕迹 | 足迹 |
| 柔性的低能量模式 | 歇脚模式 |
| 有意留出的休息日 | 停靠日 |
| 月度总结的功能名称 | 成长结算 |
| 月度总结的叙事标题 | 沿途回望 |
| 整体叙事主题 | 一路微光 |

推荐说明：

- “成长值”适合做相对功能化的累计表达
- “微光”适合做更温和、更具叙事感的可兑换资源
- “提灯”适合做余额卡片、页签或概览容器
- “心愿单”适合作为完整奖励列表或导航名称
- “心愿卡”适合作为一条具体的用户自定义奖励项
- “心愿驿站”更适合作为页面标题，不一定适合所有导航入口

## 5. 功能术语与叙事术语的关系

核心原则：

- 功能术语负责清晰
- 道路隐喻负责温度

这意味着：

- 不能把所有地方都改成隐喻词
- 用户必须一眼看懂功能是什么
- 叙事词更适合做副标题、说明文案、空状态、总结标题和视觉语境

示例一：

- 内部概念：
  - `long_horizon_task`
- 清晰 UI 标签：
  - 长期任务
- 可选叙事副标题：
  - 一段持续前行的路线

示例二：

- 内部概念：
  - `milestone`
- 清晰 UI 标签：
  - 里程碑
- 可选叙事副标题：
  - 下一个路标

示例三：

- 内部概念：
  - `reward_balance`
- 清晰 UI 标签：
  - 微光余额
- 可选叙事容器标题：
  - 提灯

推荐落地方式：

- 导航、设置、按钮、筛选项优先使用清晰功能词
- 首页卡片标题、总结页、空状态、提示语可以加入叙事温度

## 6. 核心叙事文案示例

推荐示例：

- DayNest 不是催促你赶路，而是替你收集一路上的微光。
- 今天只完成了一点点，也留下了一点微光。
- 路灯还亮着，不必急着赶路。
- 暂时停下来，也是在照顾接下来的旅程。
- 昨天稍微停了一下，今天还可以继续。
- 你已经走过了一段路，可以回头看看沿途留下的足迹。

文案基调建议：

- 温和
- 具体
- 承认微小行动也有意义
- 不制造被评判感

## 7. 成长经济文案示例

以下示例用于未来 UI 文案方向，不代表已批准实现。

### 完成任务

```text
完成《准备 PPT 初稿》
成长值 +12
收集微光 +4
```

### 完成子任务

```text
完成子任务《整理资料目录》
成长值 +4
收集微光 +1
```

### 完成 25 分钟专注时段

```text
完成一次 25 分钟专注
成长值 +6
收集微光 +2
```

### 查看当前微光余额

```text
提灯
当前微光：28
```

### 查看微光记录

```text
微光记录
你可以回头看看这些光是怎样一点点积累起来的。
```

### 兑换心愿

```text
将使用 80 点微光，
点亮《周末去咖啡店休息》。
要为自己留出这段时间吗？
```

### 微光不足

```text
现在的微光还不够点亮这个心愿。
没关系，可以先把它留在心愿卡里，慢慢靠近。
```

### 月度结算

```text
成长结算
这个月你在路上留下了不少足迹，
也为自己收集了新的微光。
```

## 8. 休息与恢复语言

DayNest 必须明确支持休息和恢复语言。

### 推荐定义

- 歇脚模式
  - 用于低能量、恢复期、想降低压力时的柔性模式
- 停靠日
  - 用户有意为自己留出的休息日
- pause windows
  - 可以翻译为暂停窗口或停靠窗口，用于计划性地放缓节奏

### 低能量语言原则

- 允许慢下来
- 允许空白
- 允许今天只做一点点
- 允许暂时只保留连接感，不要求高产出

### 明确禁止的默认方向

- 不使用惩罚性文案
- 不使用羞耻驱动的连续打卡话术
- 不因错过任务默认扣除微光
- 不把休息描述成失败、退步或浪费

### 应避免的文案

- 你失败了
- 连续打卡中断
- 今天没有努力
- 你浪费了一天

### 推荐替代文案

- 昨天稍微停了一下，今天还可以继续。
- 今天可以慢一点。
- 暂时停靠，不会抹去此前留下的足迹。
- 没有记录的日子，也不需要被评判。

## 9. 日历与时间线叙事

日历和时间线可以承接“路”和“光”的视觉语言。

### 可使用的视觉元素

- 小小的光点
- 足迹
- 路灯
- 长椅
- 路线片段
- 路标
- 安静的留白日

### 推荐映射

- 活跃日
  - 可以显示足迹或小微光
- 较高投入日
  - 可以显示更亮一些的光点
- 休息日
  - 可以显示路灯或长椅
- 空白日
  - 保持安静，不显示失败标记

核心原则：

- 空白不等于失败
- 视觉 quiet day 应当是平静的，而不是警告式的

## 10. 长周期任务叙事

长周期任务适合用“路线”来帮助用户理解持续推进，而不是用一次性完成的逻辑看待它。

推荐关系：

- project
  - 可被描述为一段旅程
- long-horizon task
  - 可被可视化为一条路线
- milestone
  - 可被可视化为一个路标
- subtask
  - 可被显示为路线上的若干步
- due date
  - 可被显示为目标抵达时间
- progress
  - 可被描述为已走过的距离

重要边界：

- 功能标签必须始终可见
- 用户不能被迫猜测隐喻的意思

## 11. 习惯叙事

习惯更适合被描述为“反复点亮路边的小灯”，而不是被描述成严苛的连续打卡压力。

推荐方向：

- 习惯的每次完成，像在路边点亮一盏小灯
- 子习惯或灵活选项，都可以满足更大的日常意图
- 暂停不会抹去已经发生的成长
- 连续性是一个信号，不是道德判断

可选示例：

- 今天的散步，也点亮了“活动身体”这盏灯。
- 这几天走得慢一点，但路边已经亮起的灯还在。

## 12. 月度结算叙事

推荐功能入口名称：

- 成长结算

推荐叙事报告标题：

- 沿途回望

### 示例结构

- 完成的行动数
- 专注时间
- 习惯打卡天数
- 收集到的微光
- 点亮的心愿
- 最突出的成长方向
- 持续时间最长的路线
- 最稳定的重复习惯

### 语气要求

- 总结证据
- 不评判用户
- 同时承认活跃日与安静日

可选示例文案：

```text
沿途回望
这个月你走过了一段不短的路。
有些日子更明亮，有些日子更安静，
它们都属于你的这段旅程。
```

## 13. 内部数据字段必须保持中性

叙事语言属于可见层，不应直接写死进内部领域标识。

推荐中性内部标识：

- `progressXp`
- `attributeXp`
- `rewardToken`
- `rewardBalance`
- `rewardTransaction`
- `rewardLedger`
- `rewardCatalog`
- `rewardRedemption`
- `restMode`
- `pauseWindow`
- `monthlySettlement`

不要直接把以下中文叙事词写进领域标识：

- 微光
- 提灯
- 心愿驿站
- 路标

原因：

- 内部标识应保持语言中立
- 未来本地化和标签覆盖会更安全
- 数据迁移时更不容易被叙事变动影响

## 15. 语言切换策略

建议策略：

- 先把中文版本打磨清楚
- 英文版本后续再设计
- 内部标识继续保持语言中立
- UI 文案和模板文案未来从本地化标签或标签注册表读取
- 当可注入标签变量可用时，模板不应硬编码中文叙事词
- 未来用户也许可以覆盖部分可见标签，但不应影响规范数据

结论：

- 中文是首个要定稿的语言
- 英文不应直接逐字硬译，而应在后续确认是否保留“道路与微光”的核心隐喻

## 16. 模板系统影响

叙事语言与模板系统的关系应当保持清楚。

原则：

- 叙事标签属于本地化层或标签注册表
- 模板负责渲染选中的可见标签
- 模板不能计算奖励
- 模板不能存储规范数据
- 模板不能成为图表数据源
- 模板未来应通过安全的渲染上下文接收标签

未来可能的安全模板变量示意：

- `{{labels.progressXp}}`
- `{{labels.rewardToken}}`
- `{{labels.rewardWallet}}`
- `{{labels.rewardRedemptionAction}}`

重要说明：

- 这些只是未来设计方向
- 当前不实现任意对象遍历
- 是否允许嵌套标签变量，应由未来渲染器安全设计单独决定

## 17. 可选视觉语言方向

推荐视觉母题：

- 路径
- 路灯
- 长椅
- 足迹
- 路线标记
- 温暖的光
- 清晨与傍晚
- 路边的小植物

应避免：

- 刺眼的红色失败提示
- 竞争排名压力
- 过重的 RPG 复杂度
- 激进的连续打卡警告
- 过于商业化的钱包视觉

视觉方向建议：

- 更像陪伴式旅程
- 少一点交易感
- 多一点温和的可见积累

## 18. 产品边界说明

- MoodNest 仍然是情绪支持助手
- DayNest 仍然是行动与个人成长账本
- Relief Toolkit 未来可以沿用路灯或休息站意象，但仍需低风险定位
- Wellbeing Tracker 仍应保持可选、隐私隔离
- 叙事语言不能把医学症状、精神痛苦或高风险情境轻描淡写

重要边界：

- 叙事温度不能覆盖风险判断
- 对敏感议题仍应优先使用清晰、谨慎、非浪漫化表达

## 19. 开放问题

- “一路微光”是否应正式成为整体主题名
- “提灯”更适合作为页面、卡片还是两者都可
- “心愿驿站”是否适合做页面标题，而“心愿单”保留为导航名称
- “足迹”是否只做视觉表达，还是也进入正文文案
- 成长值数字是否默认显性展示，还是做渐进披露
- 用户未来是否可以自定义部分叙事标签
- 英文版是否保留“道路与微光”隐喻，还是采用更朴素的产品词汇
- 停靠日是否可以显示长椅等视觉元素但不产生奖励
- 对偏好极简界面的用户，叙事视觉应允许关闭到什么程度

## 20. 保守结论

推荐方向：

- 用“一条路”和“一点光”的中文叙事来组织 DayNest 的可见语言
- 让前行、停靠、回望、点亮形成统一但低压力的产品语境
- 始终保留清晰的功能术语，避免只有隐喻没有说明
- 把休息、恢复、安静日纳入旅程，而不是纳入失败叙事
- 让内部标识保持中立，把叙事词放在未来本地化或标签层

本文不批准任何运行时代码变更。
